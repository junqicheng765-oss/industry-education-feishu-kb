# 项目模板初始化与验收

模板 v1.0：[项目模板（复制后使用）](https://lcngwcork9tw.feishu.cn/wiki/Q65Ww6VXRitVVIkv9UecM5OOn0f)。七个栏目沿用现有模板，不另造“投标、技术、履约”作为项目的直接子页；这类材料分类放进对应栏目。

## 目录与材料归属

| 项目直接子页 | 内容 |
|---|---|
| 00 项目首页与当前状态 | 项目ID、负责人、当前阶段、里程碑、范围、入口、缺口 |
| 01 需求与原始依据 | 采购/需求、客户原始材料、投标材料、合同版本及来源 |
| 02 专属方案与范围基线 | 工作方案、技术配图、已确认基线及排除项；草稿和正式承诺分开 |
| 03 决定与变更记录 | 日期、问题、决定、依据、确认角色、版本、影响、状态 |
| 04 实施、培训与协同记录 | 执行记录、培训、会议行动、依赖与阻塞；计划不等于已实施 |
| 05 验收证据与遗留事项 | 验收约定、测试、签认、遗留项；知识入库验收不等于项目验收 |
| 06 复盘与可复用成果 | 有证据的经验、适用条件、通用库引用；候选材料不自动升为案例 |

栏目页可以暂缺业务事实，必须写“当前有什么、缺什么、下一步由谁补”，未知负责人填待指派。不能保留整页模板提示就宣称完成。允许栏目下再建分类，不复制来源材料到多个栏目凑数，使用链接关联。

## 创建与修复

在本 Skill 目录执行。使用当前获授权的个人连接；`--apply` 仅执行用户已授权的创建工作。飞书 `wiki +node-copy` **只复制一页，不复制子页**，本脚本逐一复制七个栏目。

```bash
# 新项目：先查重和展示待建页，再执行同一命令加 --apply
python3 scripts/project_workspace.py init --name '实际项目名称'
python3 scripts/project_workspace.py init --name '实际项目名称' --apply

# 已有项目：只补缺失栏目，保留现有正文和资料
python3 scripts/project_workspace.py init --project '实际项目node_token' --apply

# Agent按本次真实资料填写项目根页和七个栏目，再检查
python3 scripts/project_workspace.py check --project '实际项目node_token'
```

项目根页记录：项目ID、项目负责人、当前阶段与下一里程碑、建设范围与排除项、原始依据及来源链接、权限与可引用范围、项目模板版本（v1.0）。项目ID为稳定内部ID，不冒用采购编号。栏目页沿用模板元数据字段。

初始化仅建结构，**不填业务事实、不移动旧资料**。重跑会读取实际同名页，补缺失项；出现重复同名页或返回不明即停止，查询远端结果后再修复。既有项目材料的归位须读取现行正文和目录，确定映射后按当前任务授权执行，保留原文、附件及链接。不要为“模板化”覆盖业务正文。

## 验收与约束边界

脚本检查空间、父节点、七个栏目、名称重复、未归类的直接子页、元数据、未填写模板和子树材料的在线文档类型/原件附件。输出 `structure_passed` 与 `business_pending`；失败返回非零。它不证明来源真实性、附件二进制一致、业务审批或全员权限，附件SHA-256和索引仍按入库规程另验。

初始化后仍有模板占位，Agent必须完成事实填写或具体缺口记录，再运行检查。结构通过但负责人、范围或验收证据未确认，只能报告“结构已规范，业务待补”；不得报告“方案基线已批准”或“项目已验收”。脚本的 `business_ready` 固定为 false，表示本工具不做业务审批。

此版本是Agent执行和完成验收的流程约束。直接调用CLI/API仍能绕过；团队各成员要更新本地启动配置。服务器统一写入服务和收口写权限尚未建设，不声称飞书已强制阻止不合规写入。
