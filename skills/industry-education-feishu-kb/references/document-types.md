# 文档类型与最小内容

元数据使用[正文模板](../assets/entry-template.md)。正文按用途调整，材料不足标未知，不为填满结构虚构。

| 类型 | 至少说明 | 需要防止的误用 |
|---|---|---|
| 产品档案 | 用户/场景、适用版本、功能与能力状态、限制/依赖、教学用途、演示与证据、交付/验收引用、关联方案 | 把采购要求或Demo写成已实现；专属定制写成通用可售 |
| 建设方案 | 需求与适用条件、目标、产品/教研组合及理由、建设内容、实施/验收边界、成本口径、采用版本 | 只列产品；候选工期与价格写成承诺 |
| 方案组件 | 可复用段落、适用/不适用条件、变量、事实来源、产品版本、对外引用范围 | 脱离条件复制数字或案例 |
| 教研/实训包 | 专业/岗位/能力、学习者前提、目标、系统/数据条件、任务、提交物、评价、教师指引、试用状态 | 教学设计稿当效果；真实学生材料当通用样例 |
| SOP/验收方法 | 系统版本、角色、前提、步骤、证据、异常、责任边界 | 通用方法写成项目已验收 |
| 项目首页/范围基线 | 项目ID、来源/阶段、负责人、确认范围、变更、里程碑证据、专属限制、关键入口 | 会议意见覆盖合同，历史报告冒充现状 |
| 案例/复盘 | 实际问题、时间/范围、行动、结果证据、遗留问题、复用条件、客户与数据可引用范围 | 无来源效果数字、虚构客户背书、越权对外使用 |
| 研究/政策/数据资料 | 原始来源/日期/位置、适用地域与范围、事实与分析区分、核验日期、使用边界 | 解读代替原文、统计年和发布年混用、无授权数据 |

## 产品档案正文骨架

1. 谁在什么场景使用，解决什么问题。
2. 能力表：功能项、状态、适用版本/环境、证据、依赖与限制。
3. 适用/不适用的方案及组合条件。
4. 对应课程、任务包和教学用途。
5. 演示、截图、说明、集成文档、交付与验收指引。
6. 已核实项目案例、引用范围及待确认项。

## 建设方案正文骨架

1. 适用院校、专业、建设阶段和需求依据。
2. 建设目标与可观察验收结果。
3. 产品及教研组合，引用产品档案版本。
4. 建设内容、实施依赖与责任。
5. 培训、运营支持、验收方法。
6. 数量/工期/价格的候选或确认状态、来源和条件；受限数据不写通用正文。
7. 案例、来源、待确认项和项目化时需要补的变量。

## 项目转通用知识

原始项目资料保留。抽取复用内容时核对证据与条件，删除不允许向目标读者披露的信息。方案模板不携带客户特价和专属数量；故障经验保留版本及复现条件；案例可溯源但不暴露无权限附件标题、链接或摘要。引用范围不明确时只交受限草稿。
